# Security audit remediation: 2026-11-13

The first v0.6.0 CI run passed all four Windows/Linux, Node 22/24 test jobs, but its dependency audit failed. The 18 affected package entries came from four advisory roots, including development dependencies. No audit exclusions or severity reductions are used in this remediation.

## Dependency changes

| Advisory root | Before | Remediation |
|---|---|---|
| [follow-redirects: cross-realm credential handling](https://github.com/advisories/GHSA-mrwp-f3q8-3g9p) | 1.16.1 | Resolve 1.16.3 through an override |
| [minimatch: pattern amplification](https://github.com/advisories/GHSA-g3hv-75wg-m249) | 9.0.9 and 10.2.5 | Use 11.0.8 directly and for dependencies requesting versions 7 through 11 |
| [glob: cancellation bypass](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4) | 10.5.0 and 11.1.0 | Resolve 14.0.6 for dependencies requesting versions 9 through 14 |
| [deepmerge: result-prototype poisoning](https://github.com/advisories/GHSA-gcqx-w48m-w2h4) | 4.3.1, through Jest | Replace with the development-only local compatibility patch below |

Older minimatch 3.1.5 and glob 7.2.3 consumers remain on their existing APIs; they are outside these advisories' affected ranges. Jest remains 30.2.0. This avoids npm's suggested major framework downgrades. The override ranges include the replacement versions, which is necessary for consistent npm resolution when packages are hoisted and deduplicated. The lockfile and clean-install dependency tree are checked together.

## Unpatched upstream deepmerge

Upstream has no published patched release. `tools/security/deepmerge-safe` retains the original deepmerge 4.3.1 implementation, declarations and MIT license, replacing three result-property assignments with explicit own data-property definitions. This prevents `__proto__` keys from invoking an inherited setter in target-copy and source-merge paths, while preserving normal merge options and exports.

The private compatibility package is an explicit local development dependency named `deepmerge`, and the `$deepmerge` override makes Jest use the same module. Its source and license are versioned with the repository. It is not an Ambiance runtime dependency and must not be published separately. See its README for upstream provenance and removal conditions. The clean audit reflects actual patched code and regression tests, rather than an ignored advisory or an older unpatched version.

## Validation

- Full and production-only audits report zero findings, including low severity.
- The full default suite passes 48 suites and 639 tests, with two existing skips.
- Seven dependency-security tests cover reported prototype-poisoning cases, target copying, merge API compatibility, real loopback cross-origin credential stripping, and glob cancellation during directory traversal. They also pass after a fresh lockfile installation.
- A separate loopback probe confirms that follow-redirects 1.16.1 forwards a fake cross-realm credential, while 1.16.3 strips it and retains an unrelated header. No real credentials or external redirect servers are used.
- The installed-package lifecycle pass retains its 34 checks, including real local embeddings, incremental updates and interrupted-write recovery.
- TypeScript, build and shipped skill verification pass.
- All 5,212 pre-existing benchmark files are hash-audited unchanged. No Bonsai or Luna settings change, and no frozen benchmark is rerun or overwritten.

CI now runs the full audit with `--audit-level=low`. The Windows/Linux, Node 22/24 jobs continue to run the complete default suite and packed-package lifecycle checks.

Local evidence is retained under `artifacts/security-audit/2026-11-13`, including before/after audits, tests, redirect probes, lockfile-install logs and the benchmark preservation manifest. Earlier dependency-resolution probes are retained separately from the accepted results. Nothing is published to npm by this work.
