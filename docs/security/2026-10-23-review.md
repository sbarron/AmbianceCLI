# Security update review — October 23, 2026

## Result and scope

The initial npm audit reported **16 affected dependency entries: 1 critical, 12 high,
and 3 moderate**. These are package-level audit entries, including inherited findings,
not 16 distinct vulnerabilities or 16 demonstrated application exploits. The updated
lockfile and production dependency tree both report **zero known vulnerabilities**.
A fresh installation of the packed CLI also reports zero vulnerabilities.

This review covered the npm dependency graph, advisory patch requirements, AST search
and summary subprocess execution, selected file-discovery and handoff-search paths,
API logging, and the npm package manifest. It is a targeted review, not a complete
penetration test, a historical secret scan, or a guarantee against undisclosed issues.

The checkout already contained uncommitted 0.6.0 handoff/search and skill changes.
Those changes and the version number are preserved. Nothing has been committed,
pushed, or published by this security update.

## Source findings fixed

### Shell interpretation and executable substitution in AST tooling

`src/runtime/summary/fileSummary.ts` built `npx ast-grep` shell command strings from
patterns and filenames. Double quotes did not safely preserve arbitrary filenames
on POSIX shells. `src/runtime/grep/astGrep.ts` also selected executables from the
current working directory's `node_modules/.bin`, used Windows command shims, and
fell back to shell/npx launch paths. Inspecting an untrusted checkout could therefore
execute a project-provided shim; some argument shapes could be interpreted by a shell.
This is a local code-execution risk when operating on attacker-controlled inputs,
not evidence of an exposed network endpoint or a confirmed compromise.

Both paths now resolve the native executable relative to Ambiance's installed
`@ast-grep/cli` dependency, pass arguments separately with `shell: false`, and separate
file operands from options with `--`. Summary subprocesses have a 30-second timeout
and a 10 MiB output limit. Missing binaries fail without an npx download fallback.
Availability probes clear their timers on exit/error. Regression tests cover literal
metacharacters, AST metavariables, and a project-local executable shim.

### Other inspected boundaries

- File discovery sets `followSymbolicLinks: false`, respects ignore files, and applies
  file-size and hard-exclusion filters. This is not a sandbox for every explicit CLI path.
- Handoff search binds user query, project, session, source, and limit values as SQL
  parameters; dynamic SQL structure in the reviewed query is assembled by the program.
- API log sanitization masks key/token/authorization-like fields. Handoff redaction is
  pattern-based and does not guarantee that arbitrary secrets are removed.
- The package dry run includes the new binary resolver and showed no `.env`, `.git`,
  `.ambiance`, credential, or private-key-like paths. This was a filename inspection,
  not a complete content or repository-history secret scan.

## Compatibility changes

- Transformers.js **3.8.1 → 4.3.1**, sharp **0.34.5 → 0.35.5**, and ONNX Runtime refresh.
  The sharp fixes address inherited image-decoder vulnerabilities, including a
  [librsvg issue with conditional Linux RCE impact](https://github.com/advisories/GHSA-wq5f-xc86-pv6w).
- Zod **3.25.76 → 4.6.7** fixes the
  [oversized-collection memory-exhaustion advisory](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5).
  Record schemas now declare string keys, and validation uses `ZodError.issues`.
- OpenAI SDK **5.12.2 → 6.49.0** supports the Zod 4 dependency. Build and mocked
  provider tests validate compatibility; no paid provider request was made.
- Axios **1.18.1 → 1.20.0**, adm-zip **0.6.0 → 0.6.1**, and compatible transitive
  fixes are included. The old unused `voyageai` SDK dependency was removed: the
  application routes Voyage requests through its HTTP API client, and no SDK import
  was found in source/scripts/tests. Its old optional Transformers peer is no longer installed.
- The Node engine floor is now **22**, matching supported runtime families rather
  than advertising Node 18. Use a current patched Node 22 or 24 LTS build.
  The local host is **22.12.0** and needs a separate runtime update: later Node 22
  [security releases](https://nodejs.org/en/blog/release/v22.23.0) contain fixes absent
  from that old build. The npm audit does not cover the Node executable itself.
